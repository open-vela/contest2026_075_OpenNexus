## 四、烧录

### 关键经验：烧录前必须让板子进 BootROM
否则上次固件会抢占串口导致 sftool 报 `Failed to download stub`。

**流程**：
1. 拔 USB → 按住板子物理 Reset 键 → 插 USB → 松开（板子停在 BootROM）
2. 立即烧录（no_reset，趁 BootROM 窗口）：

```bash
# Linux（设备在 VM 时）
sftool -c SF32LB52 -p /dev/ttyACM0 -b 1000000 \
  --before no_reset --after soft_reset \
  write_flash nuttx.bin@0x12010000

# Windows（设备给 Windows 独占 COM7 时，更稳）
sftool -c SF32LB52 -p COM7 -b 1000000 \
  --before no_reset --after soft_reset \
  write_flash nuttx.bin@0x12010000
```

> 注：VMware USB 透传下 RTS 复位不可靠，建议直接让 Windows 独占 USB 用
> Windows 版 sftool 烧录（已在 Windows 验证成功）。

## 五、串口查看启动/交互

串口工具必须正确处理 RTS（否则板子停在复位态）：
- 推荐 picocom：`picocom -b 1000000 --noreset --lower-rts --lower-dtr /dev/ttyACM0`
- 避免 screen/cu（会拉 RTS 复位板子）
- 用 Python/pyserial 时：打开后设 `ser.rts = True`（deassert）
- 命令需以 `\r\n` 结尾（NSH 用 CRLF）

启动成功标志：
```

ABCD
...
NuttShell (NSH)
nsh>
```

## 七、板级修复（公共仓 vendor_sifli / nuttx）

> ⚠️ 以下为公共仓改动，按规则应走官方 PR。此处导出为 patch 便于复现，见同目录：
> - `vendor_sifli_devkit_lcd_fix.patch`
> - `nuttx_mkallsyms_fix.patch`

### 7.1 vendor_sifli defconfig（devkit_lcd nsh）
- 移除 `CONFIG_SENSORS_LSM6DSL`（DevKit-LCD 无此传感器，启动报错 -5）
- 加入 FocusMate：`CONFIG_LVX_USE_DEMO_FOCUSMATE=y`
- 加入 cJSON / 字体：`CONFIG_NETUTILS_CJSON=y`, `LV_FONT_MONTSERRAT_20/32`

### 7.2 vendor_sifli sifli_ap.c（触摸 I2C 引脚）
- `PAD_PA37` → `PAD_PA30`（DevKit-LCD 触摸 I2C1 SCL 是 PA30；PA37 是 LCD VADD_EN，
  原代码是从 LCHSPI-ULP 复制残留）

### 7.3 nuttx tools/mkallsyms.py（构建 bug）
- 容忍空文件 `nuttx.empty`（首次 ALLSYMS 时为空文件导致 ELFError panic）：
  `except Exception: self.elffile = None`

## 八、focus_agent 离线模式（专属仓）
