# FocusMate：一次主动提醒（第一步）

## 范围与状态

已实现串口创建一次预约，设备离线守时，到点向 UI 投递事件并显示提醒。采用工作区真实的 `packages/ai_agent/src/infra/cron_service.c`，以独立实例编译，符号加前缀、存储隔离，轮询间隔设为 1 秒。

**本步没有启用完整 Agent、LLM、ASR 或语音播报，也没有新增 Skill。** 工具执行和通知出口暂由本地适配层承接，不宣称已经完成正式工具注册或全套 Agent 消息总线链路；后续自然语言预约需再接回正式框架。无需蓝牙联网，本轮也未启动 BLE。

## 使用

在开发板 USB UART 的 NSH 输入：

```text
focusmate_remind after 60 "写报告"
focusmate_remind list
focusmate_remind cancel <实际返回的id>
```

`after` 目前支持 1～86400 秒。第一版仅允许一项尚未到期的预约；保存并回读确认成功后才输出 `SCHEDULED ... persisted=1`。必须先运行 FocusMate UI，否则拒绝创建预约。

到点显示“该行动啦”和任务名称：

- “去专注”：查找同名未完成任务，必要时添加一项，进入时长选择；不直接开始计时，继续沿用放置手机后开始的逻辑。
- “知道了”：关闭提醒，保留原页面。
- Home：关闭提醒并执行现有 Home 行为。
- 正在录音、有未结束专注轮次或待反馈时，提醒保留并延后展示，不覆盖当前流程。

## 实现

原生 `reminder_service` 任务保持调度线程存活。一次性 cron 任务使用 `CRON_KIND_AT` 和 `delete_after_run=true`，到点执行本地 `focusmate_prompt` 适配函数。

预约保存在 `/data/focusmate/reminder-cron.json`，与正式 Agent 数据隔离。任务文字通过唯一命名的本地 JSON 事件文件传递，队列只传 28 字节事件标识，兼容板子原有 32 字节消息限制。接收端校验标识和标题；只有 UI 线程调用 LVGL，展示成功后读取的事件文件被清理。

编译开关：`-DFOCUSMATE_REMINDER=ON`。源文件位于 Ubuntu 项目 `app/focusmate/reminder/`，界面接入位于 `ui/focus_pixel.c`。源码修改及依赖的调度器版本另存于本轮产物。

## 已取得的验证证据

- Ubuntu 原生测试：直接编译真实 cron 源码，使用受控时钟验证保存、重新加载、到期前不执行、到期只执行一次及取消；通过。
- 状态测试：新增任务、同名去重、进入时长选择、放手机等待、运行中保护、列表满及空任务拒绝；通过。
- SF32LB52 固件编译通过，烧录并回读校验退出码 0。
- 实板真实预约：`due - 创建时设备 epoch = 60`。10 秒、55 秒检查均未显示提醒；到期执行一次，UI 日志出现 `SHOWN title=写报告`；随后预约数为 0，原有任务数仍为 3、专注计时未启动。
- 主机观测到执行约在 59.74 秒、显示约在 59.83 秒。这是使用整数 epoch 的秒级调度，存在取整与轮询误差，不承诺精确到毫秒或严格满 60.000 秒。
- 实板取消测试：创建 10 秒预约、拦截第二项预约、取消成功，等待 13 秒未出现触发，预约数为 0。
- 用户已确认：屏幕画面正常，点击“去专注”成功进入“写报告”的时长选择页。没有点击开始，番茄钟未自动运行。

日志：`output/firmware/2026-11-04/reminder/real-60-seconds.log`、`cancel-and-duplicate.log`、`boot-state.log`。openvela Goldfish ARM64 模拟器完整编译通过，使用独立测试数据镜像启动，实际运行提醒命令，结果另存于 `simulator-console.log`。为生成模拟器镜像补装了 Ubuntu 的 `mtools`；未使用原模拟器的用户数据镜像。

模拟器实测 3 秒预约：出现 `FIRED`、`SHOWN`，随后预约数为 0。测试结束后主动退出该独立实例，宿主 emulator 在退出过程中报告 Segmentation fault；这是退出阶段异常，未在 guest 提醒运行中出现内核断言，实板不受影响。原模拟器数据未用于本次测试。

最后的实板状态：`page=prepare tasks=4 selected=3 remaining=1500 seconds=0`，提醒已关闭、预约数为 0。新增的第四项是用户接受的“写报告”，原三项保留。

## 尚未完成

设备日历时间目前未校准；本步只验证相对延时，不支持直接输入“今晚八点”。下一步需校时并验证绝对日期/时区，之后接入自然语言理解、用户确认和正式 Skill/工具注册。重启恢复、断电保持、关机唤醒、低功耗与声音效果均未验收。持久化文件写入和软件重载测试通过，不等同于实板断电恢复通过。
