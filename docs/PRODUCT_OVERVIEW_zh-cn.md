# FocusMate 产品说明与未完成事项

版本：第一版开发说明 · 2026 年 10 月 18 日
面向：项目队友、开发协作者及演示材料编写者
状态依据：截至 2026 年 10 月 17 日最近一次代码检查和模拟器验证记录。本说明不是最终验收报告。

## 1. 产品概况

**FocusMate 是一个帮助用户启动任务、保持专注并在中断后继续的 AI 桌面专注伙伴。**

产品面向学习、课程作业、求职准备等需要持续投入的场景。用户说出想做的事，确认设备整理出的行动名称，选择本轮投入时间，再把手机放入底座开始专注。设备负责展示当前行动、计时、检测手机拿起与放回，并保留执行记录。

硬件端的主要价值是提供一个持续可见、易于操作的执行入口，让用户减少反复打开手机查看任务或计时的需要。复杂目标规划计划放到后续手机端，当前硬件界面只围绕“眼前这一件事”展开。

当前开发以 **openvela + ai_agent + LVGL** 为基础，目标开发板为 **SF32LB52-DevKit-LCD V1.2.0**。新版主要交互已经从 HTML 原型迁移到 openvela Goldfish 模拟器中的原生 LVGL 应用。

**当前可以证明的是新版模拟器的主要交互和状态逻辑可运行，尚不能证明完整产品已在实板上跑通。**

## 2. 用户场景与使用示例

小林需要完成课程报告，但任务较大，一直没有开始。使用 FocusMate 时，他先输入一个具体行动：

> “嗯，我想，那个，写课程报告第一节。”

设备展示“写课程报告第一节”，请他确认。确认后，行动进入今日任务。小林选择这项任务，选择先投入 25 分钟，把手机放入底座，计时开始。

中途拿起手机时，计时暂停；手机放回后，继续刚才的专注。25 分钟结束后，设备询问该行动是否完成。若还没做完，可以继续投入下一轮；若已完成，则标记完成并返回任务列表。

这一流程中的任务名称整理、收音和手机检测，目前均需区分模拟演示与真实实现：新版默认使用模拟语音和模拟放置事件，任务名整理采用本地口头语清理规则。

## 3. 产品结构与交互逻辑

### 3.1 页面结构

```text
待机页
  └─ 点击进入 / 模拟语音唤醒
      └─ 欢迎页：你好
          ├─ 今日任务
          │   └─ 选择行动 → 选择时长 → 等待放入手机
          │       └─ 专注计时 ↔ 暂停
          │           └─ 本轮反馈
          │               ├─ 完成 → 结算 → 返回任务列表
          │               ├─ 继续 → 选择下一轮时长
          │               └─ 其他 → 困难建议 / 本次结束
          └─ 添加行动
              └─ 开始录音 → 手动结束 → 任务名确认
                  ├─ 确认无误 → 保存 → 回到添加行动
                  └─ 重新输入 → 回到添加行动
```

Home 是独立入口：可回到待机页，并保留当前任务现场；专注过程中按 Home 会暂停，不会让计时在后台继续。

### 3.2 待机与进入

待机页展示 FocusMate 和唤醒提示，同时提供“点击进入”，供不方便说话时使用。

进入后展示“你好”，提供“今日任务”和“添加行动”两个主选项。列表页的返回操作回到欢迎页，Home 则回到待机页，两者职责不同。

唤醒提示沿用当前原型中的“你好，openvela”。**当前只有模拟唤醒入口，真实唤醒词识别尚未验收。**

### 3.3 添加行动

硬件端的产品输入方式以语音为主，添加页不要求用户在小屏幕上填写复杂表单。

1. 短按对话键，开始录音。
2. 用户描述想做的事情。
3. 再次短按对话键，结束录音；不根据停顿自动结束。
4. 展示整理后的任务名，供用户确认或重新输入。
5. 确认后保存，返回添加页，允许连续添加。

保存任务不会直接进入时长选择，也不会启动计时。未收到声音时，应返回重试，不能生成空任务。

当前任务名整理仅为本地规则，主要清理开头的部分口头语；复杂语义理解、真正的 AI 总结提炼尚待接入。模拟波形随模拟声音状态变化，不代表实时麦克风振幅。

### 3.4 今日任务与专注准备

今日任务以小屏单项浏览方式呈现未完成行动。用户选择行动后，再选择本轮专注时长，目前为 **15 / 25 / 45 分钟**。

这里的时长表示本轮投入，不是 AI 对整项任务完成时间的保证。同一行动可以跨多轮推进。

当前新版任务暂存容量为 12 项；该容量属于第一版实现限制，不是最终产品规格。模拟器首次使用提供示例任务，供体验流程。

### 3.5 手机放置与计时

| 触发情况 | 产品行为 |
| --- | --- |
| 点击开始，但手机尚未确认放入 | 显示“将手机放入底座”，倒计时不动 |
| 手机稳定放入 | 开始本轮计时 |
| 专注中拿起手机 | 暂停计时，保留剩余时间 |
| 放回手机，且暂停由拿起手机造成 | 自动继续 |
| 用户手动暂停后放回手机 | 保持暂停，需主动继续 |
| 按 Home、取消等待或已结束本轮后放回手机 | 不自动启动 |
| 选择“无法检测？直接开始” | 本轮切换独立计时，不响应手机拿起事件 |

当前模拟检测设置了 650ms 稳定窗口，用于过滤状态抖动；最终参数需要根据实际开关和底座结构调整。

手机检测只确认底座是否被触发，不能据此识别物品一定是手机，也不能判断用户拿起手机的原因。

### 3.6 本轮结束与任务完成

**计时结束不等于任务完成。** 时间到或用户确认提前结束本轮后，进入本轮反馈：

- **完成了**：标记当前行动完成，展示结算，再返回剩余任务列表。
- **继续做**：保留行动，重新选择下一轮时长。
- **其他**：选择遇到困难，或本次先结束。

困难页目前展示本地模拟的缩小行动建议，尚未调用真实 AI。采用建议会调整当前行动；不采用则保留原行动。

### 3.7 保存与恢复

新版保存任务、当前选择、剩余时间、累计投入、轮次、中断次数和恢复备注等信息。重新启动后先进入待机页，用户主动进入今日任务后，再恢复暂停现场或待确认的本轮反馈。

当前已验证正常保存和应用重新启动恢复；突然掉电、低电压和长时间存储可靠性仍需后续验证。

## 4. 界面、按键与模拟器

设备界面以 **390×450** 为设计画布，采用深绿色背景、浅绿色文字、像素伙伴和较少的主操作。新版是原生 LVGL 实现，不是在设备中运行网页；字体、局部绘制与 HTML 不完全一致。

计划使用两个实体键：

| 按键 | 计划职责 | 当前情况 |
| --- | --- | --- |
| Home | 回到待机，暂停并保留现场 | 已在测试台模拟；真实按键映射待确认 |
| 对话键 | 短按开始，再短按结束录音 | 已在测试台模拟；真实按键与收音联合验证待做 |

模拟器窗口左侧是设备画面，右侧是可滚动的开发测试台。测试台提供手机放入/拿起、声音开关、语音样例、时间快进、网络状态、低电量和充电等控制，**不会作为实际设备 UI 的功能区**。

## 6. AI Agent 与比赛要求的关系

产品目标是让 AI 帮助用户理解行动、调整行动，并在需要时主动推进；精确计时、按键响应、手机检测和暂停恢复由确定性的本地程序处理。

按此前整理的赛题基础要求，后续仍需为最终版本补齐以下证据：

- openvela + ai_agent 在指定开发板上实际运行，LLM 后端和交互渠道可用。
- 至少一个实际加载并演示的自定义 Markdown Skill。
- 至少一个可复核的“主动触发 + 执行”场景，并说明 ai_agent、工具和本地控制各自承担的职责。
- 完整用户故事、已实现功能清单、技术说明及演示材料。

当前手机拿起暂停可展示事件驱动的产品交互，但模拟事件和普通状态机本身，不能自动证明比赛所需的 Agent 能力已经达标。最终需形成真实设备事件、Agent/工具处理、执行结果及日志证据。

## 7. 未完成事项与推进顺序

### 7.1 优先事项：先核查底层路径

1. **音频支持**：核查当前 openvela 工程中麦克风采集、音频输出、功放控制和设备节点，明确哪些已有驱动，哪些需要补板级配置。
2. **联网支持**：确认当前固件是否具备可用的蓝牙网络路径。蓝牙连接或 BLE 通信成功不等于能够访问互联网；尚不能认定 PAN 已适配。
3. **GPIO 与按键**：确认空闲引脚、电平和板级按键位掩码，再确定手机检测接线及 Home/Talk 映射。

这些核查不必等待配件全部到齐，可以先读源码、检查配置并编译小型验证程序。

### 7.2 接着完成软件闭环

- 用 PCM 文件实际验证 ASR 调用链路，明确超时、空结果和失败提示。
- 接入真正的任务名提炼，保留用户确认环节；失败时不能假装得到了 AI 结果。
- 完成外放/提示音适配和调用验证。
- 根据最终联网方案实现真实连接状态、超时、重连与离线恢复。
- 检查新版与现有 ai_agent Skill、消息通道和工具接口的集成。
- 编译目标开发板版本，检查内存、字体和资源占用；模拟器固件不能直接烧录到 SF32LB52。

### 7.3 配件到齐后做实板验收

先使用 USB 供电，逐项验证屏幕/触摸/按键、手机开关、麦克风、扬声器和联网，再组合为完整流程。最后验证电池规格及接口、充电、供电切换、电量显示和独立运行。

最小完整验收路径：

> 进入 → 真实收音 → ASR → 任务名提炼 → 用户确认 → 今日任务 → 时长选择 → 实际放置手机 → 开始计时 → 拿起暂停 → 放回继续 → 本轮反馈 → 保存 → 返回列表。

补充测试包括静音、识别失败、网络中断、手动暂停、Home、取消等待、应用重启和异常掉电。真实语音唤醒应单独验收，不能用按键录音代替。
