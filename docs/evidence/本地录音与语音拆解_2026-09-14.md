# FocusMate 本地录音与语音拆解验证（2026-09-14）

## 结论

P1 本地录音链路已打通，并完成以下端到端验证：

```text
按住说话 / ptt
  -> /dev/audio/pcm0c 本地 PCM 采集
  -> 火山 ASR 流式识别
  -> FocusMate goal
  -> ai_agent 读取 focus-planner Skill
  -> DeepSeek 返回结构化计划
  -> FocusMate READY
  -> task + duration
  -> FOCUSING 番茄钟
```

本次验证使用 goldfish-arm64-v8a-ap 模拟器、16 kHz / 单声道 / 16 bit PCM。
摄像头、真机麦克风未参与本次验证。

## 代码改动

- `packages/ai_agent/src/voice/audio_capture.c`
  - 新增 NuttX audio device 后端，不依赖 `CONFIG_MEDIA`。
  - 使用标准流式接口：
    `RESERVE -> CONFIGURE -> ALLOCBUFFER -> REGISTERMQ -> ENQUEUEBUFFER -> START`。
  - 从 `AUDIO_MSG_DEQUEUE` 消息队列消费 PCM，并在消费后重新入队。
  - 使用 `/dev/audio/pcm0c`，16000 Hz、mono、16 bit。
- `packages/ai_agent/src/voice/voice_channel.c`
  - 将 `EINTR` 视为 PTT 主动停止，不再记为异常退出。
- `packages/ai_agent/src/stubs.c`
  - 移除 `CONFIG_MEDIA=n` 时遮蔽真实 voice 实现的弱符号。
- `app/focusmate/focusmate_main.c`
  - 用 `voice_channel_start()` / `voice_channel_stop_with_text()` 替换原来的
    `next_task_name()` 假输入。
  - 识别文本直接交给现有 `cmd_goal()`。
- `app/focusmate/ui/focus_ui.c/.h`
  - “按住说话”接入 `PRESSED`、`RELEASED`、`PRESS_LOST`。
- 板级 `goldfish-arm64-v8a-ap/defconfig`
  - `CONFIG_TLS_NCLEANUP` 从 2 提升到 8，避免 FocusMate 主线程内
    ASR TLS 清理栈溢出。
- `app/focusmate` 栈提高到 40960 字节，满足 LVGL 32 KB 要求。

## 模拟器验证步骤

```text
sh -c 'ai_agent </dev/null &'

```

## 边界说明

- 触摸屏按住/松开事件已编译并通过代码路径审查；本次 headless 回归主要使用
  FocusMate 的 `ptt` 调试命令，它调用与触摸屏相同的
  `voice_capture_start()` / `voice_capture_finish()`。
- ASR、LLM、Skill 读取均走真实云端链路。
- 音频播放仍走旧 `media_player`，在 `CONFIG_MEDIA=n` 的 goldfish 配置下会失败；
  这不影响本轮录音与 LLM 拆解闭环，但会造成系统后续无法播放 TTS。
