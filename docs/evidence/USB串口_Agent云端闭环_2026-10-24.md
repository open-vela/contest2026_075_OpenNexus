# FocusMate USB 串口 Agent 云端闭环验证

日期：2026-10-24（Asia/Shanghai）。硬件：SF32LB52-DevKit-LCD，Windows COM5。

## 验证结论

已完成真实开发板两轮基础对话：

1. 用户输入“请只回复：USB链路已打通，校验码482731。”
2. 设备端官方 ai_agent 核心构造 LLM 请求，USB 串口输出请求帧。
3. Windows 转发程序通过 HTTPS 请求 DeepSeek，HTTP 200，将完整响应送回板子。
4. 板端解析并输出“USB链路已打通，校验码482731。”
5. 再问“上一条用户消息里的校验码是什么？只回复数字。”
6. 第二次 HTTPS 请求 HTTP 200，板端输出“482731”。

记录：`docs/evidence/serial-agent-two-turns-20261024.log`。两次请求长度分别 3286、3454 字节，响应分别 495、461 字节；设备记录的模型调用耗时分别约 1152、1030 毫秒。本次有两次真实 HTTP 请求，不依赖本地预设回复或模型缓存。第二轮证明本次运行期间的会话上下文可用；不能据此认定断电保存成功。

## 端侧与电脑职责

端侧编译并运行 packages/ai_agent 中的 message_bus、agent_loop、context_builder、memory_store、session_mgr、llm_proxy、llm_parse、llm_router、llm_cache、config_store、skill_loader、tool_guard 等原有模块。单独增加 `serial_agent` 入口与串口 HTTP 传输适配。

电脑只校验允许访问的主机/路径、注入 Authorization、执行 HTTPS、把响应送回板端。提示词构造、会话读取、Agent 循环、模型回复解析在设备上完成，电脑不调用本地 Agent 替代设备执行。

这是一份**最小串口验证配置**，并非官方完整 ai_agent 主程序已经全面移植完成。`CONFIG_EXAMPLES_AI_AGENT_VELA` 仍未启用；验证入口直接编译上述官方核心源码。工具列表明确为 `[]`，视觉明确返回不支持。没有运行真实语音、任务拆解、Skill 工具调用、主动执行、Wi-Fi、BLE 或通用 IP 网络接口；UI 暂未调用该验证入口。

日志中的 router “No available backend”表示未注册多模型路由后端；本测试使用已配置的单模型 llm_proxy 直接请求路径，并不代表实际云端请求失败。

## 构建与固件

在已有可编译 SF32LB52 CMake 配置基础上：

```sh
cd ~/openvela
export PATH="$HOME/openvela/prebuilts/tools/linux/x86_64:$HOME/openvela/prebuilts/gcc/linux-x86_64/arm-none-eabi/bin:$HOME/.local/bin:$PATH"
cmake -B cmake_out/sf32lb52_devkit_lcd -S nuttx -DFOCUSMATE_SERIAL_AGENT=ON
cmake --build cmake_out/sf32lb52_devkit_lcd -j4
```

CMake 和链接通过。固件 SHA256：`5bf0017e86f03028a12e8896bd57675d832f7d83d763d4cccfe1ebc2cae39dbe`。Windows 保存为 `output/firmware/2026-10-24/focusmate-sf32lb52-serial-agent.bin`。写入地址 `0x12010000`，sftool `write_flash --verify` 返回 0。

本版本也包含前一轮 speaker_test 关闭无用 DMA 填充中断的源码修正，但本轮未再次播放声音验收。

## 复现

1. 开发板连接 Windows，关闭其他占用 COM5 的串口工具。
2. 从模板在仓库外创建私有 JSON 配置，填入自己的 API Key；不要加入 Git。
3. 开发板复位后保持原生 NSH 可用，运行 PowerShell：

```powershell
./tools/serial_bridge/focusmate-usb-bridge.ps1 -Port COM5 -ConfigPath '你的私有配置绝对路径'
```

脚本会启动前台 `serial_agent`，等待 ready，执行两轮测试并打印请求状态、板端回复。默认日志位置是 Windows 工作区的 `output/firmware/2026-10-24/serial-agent-test.log`。程序没有自动发现串口；端口不同时传入正确的 Port。

串口为 1,000,000 波特率；烧录工具使用 115200，两者用途不同。帧以 `@FM@` 开头；电脑返回 JSON 行时分块限速，避免接收缓存溢出。请求白名单仅允许 `api.deepseek.com/v1/chat/completions`；响应超过板端容量时返回明确错误，不静默截断。HTTPS 证书由电脑默认网络库校验；此方案把 TLS 和凭证信任边界放在电脑端，并非设备端 TLS 验收。

本轮曾发现官方核心发送“稍等，处理中...”等进度语，初版脚本将其误判为最终回复；脚本已按当前源码的三种状态语过滤，之后重新完成两轮测试。该文本过滤只适用于当前验证版本，正式渠道应增加结构化的进度/最终回复类型。

测试入口会占用前台串口，不提供退出命令。测试后短按 RESET 退出入口，重新进入正常 FocusMate UI；不要同时启动两次 serial_agent。本次测试结束已复位，`ps` 确认仅正常 `focusmate -d` 和 NSH 运行。
