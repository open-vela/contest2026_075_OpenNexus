# SF32LB52 Home mapping repair (2026-10-24)

The previous build had no CONFIG_FOCUSMATE_HOME_MASK, so the application defaulted to zero and ignored Home presses. The board driver exports KEY2 on PA11 as BUTTON_KEY2_BIT (0x1); KEY1 is not exported by this driver.

Commit 4dfd29b uses the board-defined KEY2 bit as the SF32LB52 fallback and logs button initialization/presses. Explicit Kconfig values still override the fallback. Simulator defaults remain unchanged.

CMake build succeeded. Firmware SHA256: 219b594e4426c667e181bb766ec4cfa3967284b35c77937192e28e025534edad. Windows COM5 sftool write_flash --verify completed with exit code 0. Boot log confirmed `[pixel-key] device=5 home=0x1 talk=0x0`, LCD/input opened successfully and focusmate -d remained running.

Physical KEY2 press/navigation verification is pending the user's test. Do not treat boot initialization alone as physical-button acceptance. Prior firmware and old flash app-region backup are retained on the host.

The vendor board defconfig also has HOME_MASK=0x1 and TALK_MASK=0x0 staged as a workspace change. resetconfig failed on a stale generated apps/inertial/Kconfig reference; the build used the saved complete board config and the board-header fallback. The application commit is sufficient for this flashed binary.
