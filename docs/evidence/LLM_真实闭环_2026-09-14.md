# FocusMate × ai_agent × DeepSeek 真实闭环验证记录

> 验证时间：2026-09-14（Asia/Shanghai）
> 环境：QEMU 模拟器 `goldfish-arm64-v8a-ap`（与官方 ai_agent defconfig 逐行一致）
> 模型：`deepseek-chat`（DeepSeek 官方 API，HTTPS）

## 一、链路

```
FocusMate (velaclaw_client_open / velaclaw_ask)
        │  channel = local_client
        ▼
ai_agent daemon (openvelaClaw)
        │  Skills 汇编 + 工具调用 + LLM Router
        ▼
api.deepseek.com /v1/chat/completions   (TLS1.2)
```

```
  [4/4] 核对并发送周报
```

要点：

- ai_agent **自主调用 `read_file`** 读取设备端 Skill（不是应用硬拼 prompt）。
- LLM 按 Skill 约束产出 **2–4 项任务、不预测分钟数**。
- FocusMate 解析成功并进入 READY，**没有走本地 fallback**。
- 端到端耗时 **约 2.8 秒**。

## 五、真正打通前修掉的四个问题

| # | 问题 | 影响 | 修复位置 |
|---|---|---|---|
| 1 | `vela_tls` 读取循环对 **chunked** 响应没有结束条件，一直读到服务器 60s 后断开 | 每次 LLM 调用卡 **61 秒**，超过 60s 看门狗 → 全部超时 | `apps/packages/ai_agent/src/infra/vela_tls.c`：识别终止块 `0\r\n\r\n` 后立即结束 |
| 2 | ai_agent 对 `local_client` 通道也推送“让我查一下…”工作态消息，而 SDK 的 tap **只投递第一条**消息 | 应用只收到状态语，真实回复被丢 | `agent_config.h` 增加 `AGENT_CHAN_LOCAL_CLIENT`；`agent_loop.c` 的 `send_working_status()` 跳过该通道 |
| 3 | FocusMate 把 Skill 写到 `/data/agent/skills/`，而 ai_agent 的 `AGENT_SKILLS_DIR` 是 **`/data/ai_agent/skills/`** | Skill 从未进入提示词；`read_file` 返回 “file not found”（61 字节） | `app/focusmate/Kconfig` + `focus_agent.c`：默认目录改为 `/data/ai_agent/skills` |
| 4 | FocusMate 只认以 `{` 开头的回复，模型常把 JSON 包在 ```json 围栏里 | 解析失败 → 回退本地计划 | `focus_agent.c`：取最外层 `{...}` 再交给 cJSON |

> 第 1、2、3 条属于 ai_agent 公共仓（`packages_ai_agent`）与 `vendor` 板级问题，需按赛题要求
> 向对应公共仓 `dev-ai-contest-2026` 提 PR。

## 六、复现步骤

```bash
# 1. 构建
./build.sh vendor/openvela/boards/vela/configs/goldfish-arm64-v8a-ap/ --cmake -j8
# 2. 启动模拟器
./emulator.sh cmake_out/vela_goldfish-arm64-v8a-ap
# 3. 起 ai_agent（后台）并配置 LLM
nsh> ai_agent &
vela> router_set deepseek <API_KEY>
# 4. 起 FocusMate（前台，会自动连接 ai_agent）
nsh> focusmate
focusmate> goal 写项目周报
```

> 注意：模拟器上 ai_agent 的 CLI 与 NSH 共用 stdin。可用 `sleep 60` 先把 NSH 占住，
> 再把 `router_set` 交给 ai_agent 的 CLI。
