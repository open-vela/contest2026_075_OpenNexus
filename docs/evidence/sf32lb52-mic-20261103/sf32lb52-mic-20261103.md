# FocusMate 板载麦克风实板验证

日期：2026-11-03。目标板：SF32LB52-DevKit-LCD V1.2.1，Windows COM5，Ubuntu 编译。

当前状态：诊断固件已编译、烧录并校验。板载麦克风的声学输入已通过受控提示音验证：确实采到了电脑扬声器发出的声音。人声清晰度与 UI/ASR 接入尚未验收。

## 初检结果

- Windows 已识别 CH343 COM5，NSH 通信正常，`focusmate -d` 正在运行。
- 旧固件无 `/dev/audio`，`.config` 未启用 `CONFIG_AUDIO`，NSH 没有录音命令。这说明原程序尚未接通真实收音链路，不能据此判定麦克风损坏。
- `/dev/adc0` 是通用 ADC 设备，不等同于音频录音设备。
- 厂家资料说明此板集成模拟 MEMS 麦克风。参考：[开发板音频接口](https://wiki.sifli.com/board/sf32lb52x/SF32LB52-DevKit-LCD.html)。

## 本轮实现

新增 `app/focusmate/diagnostics/mic_test.c`，由 CMake 开关 `FOCUSMATE_MIC_TEST=ON` 注册为 NSH 命令。板级增量补丁为 `patches/board/mic-test-cmake.patch`，基于上一版已运行的工程应用。

| 命令 | 用途 |
|---|---|
| `mic_test record` | 采集 3 秒，前 250 ms 预热数据丢弃，数字增益 0 dB |
| `mic_test record 12` | 同样采集，数字增益 12 dB；允许 -12～24 dB |
| `mic_test stats` | 每半秒的平均绝对幅值、峰值和削顶样本数 |
| `mic_test play` | 从已连接扬声器回放上一次成功录音 |
| `mic_test dump` | 导出本地 PCM16，附采样参数和 FNV-1a 校验 |

格式为 16 kHz、单声道、有符号 16 bit 小端 PCM。使用芯片 AUDCODEC ADC0、MIC_BIAS 与 DMA1 通道 8；回放使用 DAC0 和 PA10 功放控制。DMA 采用有限长度、无中断的轮询方式，超时会退出并清理音频路径。固定录音缓冲区位于内部 SRAM，共 104,000 字节；这只是诊断配置，后续连续收音应改为较小的双缓冲。

时钟配置与启停顺序参考厂家 [SiFli-SDK drv_audcodec_m.c](https://github.com/OpenSiFli/SiFli-SDK/blob/a3d720121c2c66cb6cffa758e90191db3340ad61/rtos/rtthread/bsp/sifli/drivers/drv_audcodec_m.c)。本轮是 openvela 上运行的芯片 HAL 诊断，尚未提供标准音频 lower-half、ASR、语音唤醒或 UI 真实收音能力。

## 编译与固件

在已有工具链和板级工作区中：

```sh
cd $OPENVELA_ROOT
cmake -B cmake_out/sf32lb52_devkit_lcd -S nuttx -DFOCUSMATE_PHONE_GPIO=ON -DFOCUSMATE_MIC_TEST=ON
cmake --build cmake_out/sf32lb52_devkit_lcd -j4
```

- 构建退出码 0；原有开关 GPIO 与 serial_agent 诊断配置保留。
- 固件：`output/firmware/2026-11-03/focusmate-sf32lb52-mic.bin`，2,497,500 字节。
- SHA256：`38350d7bcbd65833b868a2c8b9c34fdbe9d53d031754c740f9a956f362069d32`。
- 链接静态 SRAM 使用 241,608 B / 512 KB，不代表运行时峰值。
- 回退固件：`output/firmware/2026-11-02/focusmate-sf32lb52-phone.bin`；Ubuntu 备份在 `$HOME/focusmate-backups/pre-mic-20261103/`。
- 写入地址仍为 `0x12010000`，沿用 sftool `write_flash --verify`。

## 验收项目

1. 烧录校验通过，UI、开关节点、NSH 仍正常。
2. 实际 DMA 完成且录音时长符合预期。
3. 说话与安静时的音量有可解释的差异，波形不是全零、固定值或连续削顶。
4. 扬声器能回放本人说话内容；采集的 PCM 能导出为 WAV，字节数及校验一致。

录音文件只保存在本机用于验证，不上传云端或 GitHub。

## 实测结果

- 烧录使用 `write_flash --verify`，退出码 0。NSH 新增 `mic_test`，`focusmate -d` 仍正常运行，`/dev/phone0` 仍为输入上拉。
- 环境采样和提示音采样的 DMA 均完成，耗时分别为 3260 ms、3259 ms，符合 3 秒录音加 250 ms 预热。丢弃预热后，均为 48,000 样本、96,000 字节、3.000 秒。
- 环境采样：RMS 7.180，峰值 29。此处只是当时环境记录，未要求用户保持绝对安静。
- 用 Windows 默认音频输出播放三个短音；开发板只开启 ADC 收音，采集期间未开启板端 DAC。采到的波形中能对应找到三个频率，顺序一致，因此并非仅靠 DMA 计数推断麦克风正常。
- 板端回放命令执行成功，DMA 耗时 3015 ms，返回 0，随后 `focusmate -d` 仍运行。此处仅确认 PCM 输出执行链路，尚未获得本次回放的人工听音反馈。

| 声音 | 代表性采样窗的频率幅度 | 环境记录同频率最大幅度 |
|---|---:|---:|
| 1000 Hz | 340.595 | 0.191 |
| 2000 Hz | 161.462 | 0.233 |
| 1500 Hz | 480.952 | 0.214 |

提示音录音总体 RMS 240.604，峰值 668，无削顶样本。数值为 PCM 样本单位，不是声压级或经校准的麦克风性能指标。声源经过电脑音频系统有延迟，此测试只确认频率、先后关系与真实拾音，不能用来宣称端到端延迟。

原始串口导出和解码后的 PCM 均通过 FNV-1a 校验：环境 `f9627796`，提示音 `fdcf7c37`。WAV、JSON 统计、烧录/启动/采集日志保存在 `output/firmware/2026-11-03/`。

结论：板载麦克风、偏置/音频 ADC 和采集到内存的链路可用。此前界面没有真实识别反应，存在明确的软件链路未接通原因；这次没有验证语音识别准确率、远场人声清晰度或唤醒词。
